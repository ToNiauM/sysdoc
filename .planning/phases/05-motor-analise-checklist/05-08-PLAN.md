## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `~/.sysdoc/config.json` → processo do motor | segredos de API entram em memória |
| processo do motor → APIs de terceiros (HTTPS) | conteúdo de documento oficial sai da máquina |
| resposta do provedor → estruturas internas | JSON não confiável é parseado e usado |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-24 | Information Disclosure | chave de API em log, exceção, relatório ou commit | mitigate | chave lida só no momento da chamada por `chave_do_provedor`; ausente de `ConfigDvi` e de qualquer `__repr__`; mensagens de erro de HTTP omitem cabeçalhos; teste `TestSegredo` cobre o caso 401 |
| T-05-25 | Spoofing | endpoint de provedor substituído por TLS desabilitado ou URL configurável arbitrária | mitigate | URLs fixas por adaptador no código, `verify` no default do `requests`, `verify=False` proibido e verificado por grep |
| T-05-26 | Tampering | resposta do provedor com JSON malformado ou campos extras | mitigate | parsing estrito, um retry com o erro anexado, degradação para item `pendente` com `falha_estruturada`; nenhum `eval`/`exec` sobre a resposta |
| T-05-27 | Denial of Service | provedor pendurado ou resposta gigante | mitigate | `timeout` explícito em toda chamada e `max_retries` limitado a 1 |
| T-05-28 | Information Disclosure | conteúdo sigiloso do processo enviado a provedor não autorizado | accept | envio é a finalidade do produto; mitigação operacional: o alvo é sempre declarado pelo usuário (D-16) e registrado no relatório de execução |
</threat_model>
