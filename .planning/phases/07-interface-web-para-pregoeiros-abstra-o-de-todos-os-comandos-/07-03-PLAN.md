Criar `sysdoc_web/processos/management/commands/runworker.py` — `BaseCommand` com argumento `--intervalo` (float, default `2.0`) e `--uma-vez` (flag, para teste). Ao iniciar: chama `fila.sanear_jobs_orfaos()`. Laço: `reivindicar_proximo()`; se `None`, dorme `intervalo` (ou encerra, se `--uma-vez`); se houver job, executa `_executar(job)` e volta ao laço. Tratar `KeyboardInterrupt` marcando o job corrente como `interrompida`.

`_executar(job)` faz, nesta ordem, importando `sysdoc` e `sysdoc_dvi.pipeline` **como módulos Python** (proibido `subprocess`, proibido `sysdoc_dvi.cli`):
1. Grava `job.etapa = "Lendo os documentos do processo"` e salva.
2. `sysdoc.prepare(str(servicos.caminho_do_processo(job.processo.slug)))` dentro de `try`, capturando `SystemExit` e `Exception`.
3. Define o callback `def _sink(evento)` que atualiza `job.etapa = progresso.texto_da_etapa(evento)`, e quando `evento.etapa == "itens"` também `job.itens_concluidos = evento.atual or 0` e `job.itens_total = evento.total or 0`, salvando com `update_fields` para não sobrescrever campos concorrentes.
4. `rc = pipeline.executar_run(caminho, tipo=job.processo.tipo_verificacao or None, progresso=_sink)`.
5. `rc == 0` → `fila.concluir(job, "concluida")`. `rc != 0` → `fila.concluir(job, "falhou", mensagem_erro=MENSAGEM_FALHA)`.
6. Qualquer `Exception` ou `SystemExit` não previsto → registrar com `logger.exception(...)` (o traceback vai para o log do servidor) e `fila.concluir(job, "falhou", mensagem_erro=MENSAGEM_FALHA)`.

`MENSAGEM_FALHA` é a constante literal, em português, definida em `runworker.py`: `"Não foi possível concluir a análise deste processo. Procure o administrador do sistema e informe o nome do processo e o horário da tentativa."` — nenhum traceback, nome de provedor, alvo de modelo ou caminho de arquivo entra em `mensagem_erro` (D-17, D-05, D-06). O `logger` é `logging.getLogger("sysdoc_web.processos.worker")`.

| Boundary | Description |
|----------|-------------|
| slug do processo → caminho em disco | Único dado da requisição que influencia caminho de arquivo |
| worker → pipeline DVI | O worker executa código que chama provedores externos e gasta crédito real |
| pipeline → `mensagem_erro` no banco | Texto de exceção pode conter caminho, provedor ou fragmento de credencial |
