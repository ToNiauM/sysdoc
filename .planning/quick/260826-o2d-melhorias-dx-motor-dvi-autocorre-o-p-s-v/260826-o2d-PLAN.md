Formato exato do erro de acentuação emitido por `templates/validate_sysdoc.py` (linha 283, imutável):

    f"{label}: termo sem acentuação `{match.group(0)}`; use `{accented}`"

Os delimitadores são crases. `match.group(0)` preserva a caixa original do texto encontrado; `accented` é a forma canônica do dicionário `PT_BR_ACCENT_TERMS` (148 termos, algumas entradas já capitalizadas, ex.: `"brasilia": "Brasília"`).

Rótulos (`label`) possíveis, produzidos por `validate_generated_language` (linhas 395-422) — **todos os índices são base 1**:

| label | campo no JSON |
|-------|---------------|
| `raiz.titulo`, `raiz.subtitulo`, `raiz.parecer_executivo`, `raiz.nota_integridade` | chave de mesmo nome na raiz |
| `projeto.órgão`, `projeto.objeto` | `data["projeto"][chave]` |
| `metadados[N].label`, `metadados[N].valor` | `data["metadados"][N-1][chave]` |
| `secao_etp.parecer_documento`, `secao_tr.parecer_documento` | `data[secao][chave]` |
| `itens[N].item`, `itens[N].para`, `itens[N].parecer`, `itens[N].fundamento` | `data["itens"][N-1][chave]` |

O campo `de` **nunca** é checado por acentuação (é literal por contrato) e nunca pode ser reescrito.

Saída estruturada do validador (`main()`, imutável) — é o canal a usar:

    python3 templates/validate_sysdoc.py <json_path> <project_dir> --json
    # stdout: {"valid": bool, "errors": [str, ...]}
    # returncode: 0 se válido, 1 se há erros, 2 se falhou ao ler

`ResultadoItem` expõe `checklist_id` e `classificação` (`sysdoc_dvi/tipos.py`).
